# 小李桌面内置小李全联：集成架构基线

## 产品目标

用户安装「小李桌面」后，即可从桌面直接使用「小李全联」的局域网设备发现、发送、接收、进度、历史和文件管理能力；不要求用户再单独安装小李全联 APK。小李全联仍可作为独立应用继续发布，两种入口共用同一套传输实现。

## 总体原则

1. **单 APK、双入口**：小李桌面 APK 内包含快传功能模块；桌面首页提供「小李全联」入口，用户无需额外下载应用。
2. **传输核心独立**：桌面 UI 与快传 UI 分离；设备发现、协议握手、文件流、校验、接收确认、后台服务不得依赖桌面 Canvas 或页面生命周期。
3. **复用而非重写**：优先抽取小李全联现有 Android 传输实现为可复用 Android Library；不复制一份后分别维护，不因桌面视觉改造重写传输协议。
4. **兼容既有设备**：保持已发布协议的握手、端口/服务发现、文件清单、确认流程和校验语义；新增协议能力必须向后兼容，并通过旧版互传测试。
5. **用户明确授权**：附近设备发现、接收文件、通知等按 Android 版本申请必要权限；接收端先弹出发送方/文件数量/总大小确认，拒绝也必须可用。
6. **不常驻滥用**：接收服务默认关闭，只在用户明确开启后启动；退出快传页面不能中断正在进行的传输。
7. **跨设备自适应**：快传页面复用小李桌面统一蓝白视觉语言，但分别适配电视遥控器、手机触摸、平板触摸/鼠标/键盘。

## 目标模块边界

后续 Gradle 多模块结构：

- `:app`：小李桌面宿主。负责 Launcher Activity、首页/应用抽屉、全局导航、壁纸、系统入口和宿主生命周期。
- `:feature:quanlian`：小李全联功能 UI。负责附近设备、发送队列、接收请求、传输进度、历史记录等页面；不实现底层协议。
- `:core:transfer-api`：稳定接口与数据模型，例如设备、文件任务、传输状态、进度、错误和用户确认事件。
- `:core:transfer-android`：Android 平台实现，包含 NSD/局域网发现、前台接收服务、发送服务、文件访问与 MediaStore 保存。
- `:core:transfer-protocol`：协议编解码、握手、文件清单、分块流、SHA-256 校验、兼容版本处理；尽可能保持平台无关。
- `:core:device`：设备身份、设备名称、最近设备和能力信息。
- `:core:storage`：传输历史、偏好设置、下载目录和任务状态持久化。

依赖方向：`:app` -> `:feature:quanlian` -> `:core:transfer-api`；Android 实现由宿主通过依赖注入/工厂提供给 API。UI 不得直接创建 Socket、NSD listener 或前台服务。

## 核心 API 草案

- `DeviceDiscovery.start()` / `stop()` / `observeDevices()`
- `TransferManager.send(files, device)`
- `TransferManager.observeTasks()`
- `TransferManager.cancel(taskId)`
- `ReceiveManager.startListening()` / `stopListening()`
- `ReceiveManager.observeIncomingRequests()` / `respond(requestId, accept)`
- `TransferHistory.observe()` / `clear()`

数据层使用不可变模型：`DeviceInfo`、`TransferTask`、`IncomingRequest`、`TransferProgress`、`TransferResult`。页面只消费状态流和发出用户操作。

## 桌面入口与体验

- 首页常用应用区可放置「小李全联」入口；应用抽屉也有固定的「小李全联」功能入口，不依赖系统安装应用列表。
- 进入后提供「发送」「接收」「传输记录」三个主区域。
- 电视：遥控器方向键/确认/返回完整可用。
- 手机：触摸选择、滑动和系统分享入口。
- 平板：触摸、鼠标和键盘可用。
- 接收请求必须清晰显示设备名称、文件数量、总大小，并提供接收/拒绝。
- 传输进行中离开页面或返回桌面，后台服务继续工作；通知显示必要状态，点击通知可回到传输页面。

## 从现有代码迁移时的审计要求

当前小李全联 Android 代码存在 Activity 内聚合 UI、NSD 发现、发送选择与页面状态的情况；发送/接收前台服务相对独立。迁移时：
- 先逐项盘点正式稳定分支的协议版本和真实传输代码，再抽取；不要以实验分支或旧 APK 反推最新协议。
- 将 Activity 中的设备发现、网络会话、文件选择/元数据、历史记录逐步拆出；不要一次性大改传输协议。
- 发送/接收前台服务、广播/事件和通知统一收口到 Android 实现层。
- 保留文件确认、SHA-256、取消、失败反馈、进度/速度和已有互通行为。
- 不把小李全联原 MainActivity 整体嵌入桌面；只复用功能和服务，桌面由小李桌面统一承载。

## 实施顺序与验收门槛

1. **架构骨架**：建立 Gradle 模块、接口、数据模型、依赖方向；确保原桌面仍可独立编译运行。
2. **传输核心抽取**：先迁移并回归测试发现、接收服务、发送服务和协议，不改变网络行为。
3. **桌面入口与功能 UI**：实现内置快传页面，支持触摸和遥控器；原独立小李全联仍可构建。
4. **跨设备互通测试**：小李桌面 ↔ 小李全联独立版，手机 ↔ 电视，电视 ↔ 手机；覆盖发送/接收、拒绝、取消、断连、校验失败、大文件和后台运行。
5. **权限与发布**：按 Android 版本处理通知、局域网/附近设备权限；最终仅安装小李桌面 APK 即可使用内置快传。

## 当前状态

- 已建立 `:core:transfer-api` Kotlin/JVM 模块，定义设备、文件、传输任务、接收请求等共享模型，以及设备发现、发送、接收和历史接口。
- 已建立并由 `:app` 引用 `:feature:quanlian` Android Library；当前分支已包含完整度较高的快传 Activity 页面、局域网发现接入、发送/接收前台服务和传输历史，但 UI 仍直接依赖 Android 实现，尚未完成 API 驱动与依赖注入解耦。
- 当前实现不应描述为“只有入口元数据”，也不能视为已经完成真实设备互通验收。
- 小李全联此前确认的 `v1.0-development`（commit `01ed793`）是开发测试分支，不是正式稳定版；截至本次审计，尚未识别出正式稳定分支或正式 release。因此禁止直接把该开发分支的发送/接收实现迁入生产模块。
- 下一步必须继续核实小李全联仓库的正式发布来源；在确认之前，只推进接口、宿主导航和 UI 壳层，不迁移网络协议或后台服务。


### 传输源代码审计补充（2026-11-19）

已检查小李全联仓库当前公开 refs：
- `main` 当前仅含 README；没有可供迁移的 Android 源码。
- Git tags 与 GitHub releases 均为空，暂时没有可验证的正式发布标签或 release APK 来源。
- `v1.0-development` 保留旧版 Android 实现，但它不是正式稳定版，不能作为默认迁移源。
- 当前代码量较完整的候选是 `feature/windows-desktop`（commit `dc7ca4c`）；包含 Android 发送/接收前台服务、LAN/NSD/UDP 发现、设备身份与 TLS 指纹校验，并带 Windows 客户端。但其 README 明确标注项目仍处开发初期，因此只能作为待验证候选，不能称为稳定版。

候选协议与集成风险：
- 发送端使用 `QUANLIAN4`；接收端同时兼容 `QUANLIAN2`、`QUANLIAN3`、`QUANLIAN4`。QUANLIAN4 包含续传偏移与批量确认，不能用旧版 QUANLIAN2 代码替换。
- 发现同时涉及 NSD 与自定义 UDP；连接层使用设备证书 SHA-256 指纹校验的 TLS。迁移必须连同设备身份、证书持久化/恢复策略一起审计，不能只搬两个 Service 文件。
- 候选 Android 工程 `minSdk 26`，而小李桌面目前 `minSdk 23`；并依赖 Bouncy Castle。直接复制会造成最低系统版本和依赖冲突，必须先做 API/依赖兼容性处理。
- 接收端支持断点续传临时文件、SHA-256 校验、接收确认、通知和前台服务；这些行为应保留并覆盖异常场景测试。

执行决定：
1. 不把任何当前开发分支冒充正式稳定版，也不直接合并整个 Android App。
2. 将 `feature/windows-desktop` 作为当前最完整候选，先做独立构建与协议/安全审查；必要时与其他 feature 分支逐项比对。
3. 在审查通过后，按 `transfer-api → protocol/device → Android discovery/services/storage` 的顺序抽取；先在独立集成分支验证，再合入 `main`。
4. 必须保留 QUANLIAN2/3/4 互通能力、TLS 身份校验、接收确认、SHA-256、续传、取消和后台通知；不得降低安全性来换取快速接入。
